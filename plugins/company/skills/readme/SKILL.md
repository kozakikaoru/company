# README 作成 — `/company:readme`

README を作成するスキルである。エンドユーザー向けの宣伝文ではない。

## 起動時の流れ

1. リポジトリから抽出できる情報を集める(package.json、主要な設定ファイル、ディレクトリ構成、使用フレームワーク・言語・DB・テスト)。
2. 不足している **必須情報** だけをユーザーにテキストで確認する。
3. README の全文を作成してユーザーに提示し、直したい箇所があれば指摘してもらう。
4. ユーザーが承認したら `README.md` に反映し、PR を作成する。

## 抽出・確認する情報

**必須**(無ければユーザーに聞く):

- プロジェクト名(タイトル)。
- サービス概要(1 行、三人称で書く)。
- 技術スタック(フレームワーク・言語・DB・テスト等。package.json 等からの自動抽出を優先する)。

**あれば良い**(リポジトリから拾えれば使い、無ければ省略する):

- 特徴を抽象化する材料(機能リスト、解決する課題、UX 上の工夫)。
- 画面イメージ(`docs/images/` 配下の画像パス)。
- 実装上の工夫(設計判断、トレードオフ、独自の最適化)。
- 環境変数の定義(`.env.example` 等から取得する)。
- ディレクトリ構成(`tree -L 2 src/` 等で取得する)。
- プライバシー・データ方針(個人情報を扱うサービスの場合)。

## トーン・文体の必須ルール

| 項目 | ルール |
|---|---|
| 二人称 | 「あなたの」を使わない。利用者向け文章ではないので三人称的に書く。 |
| 数値・実装詳細 | 具体的な数値や内部コンポーネント名を本文に出さず、本質を抽象的に書く。 |
| 括弧の順序 | 「日本語名(英語/URL/パス)」の順で書く。◯「プライバシーポリシー(`/legal/privacy`)」/ ✗「`/legal/privacy`(プライバシーポリシー)」。 |
| 誇張表現 | 「最強」「圧倒的」「世界初」などを使わない。 |
| 正しい日本語 | 「頭痛が痛い」のような重言や、ねじれた文を避け、文法的に正しい日本語を書く。 |
| 不要セクション | 「謝辞」「ライセンス」は基本入れない。 |

## 構成テンプレート(基本この順番)

以下のセクション順で書く。

- `# {タイトル}` — 直後に 1 行のサービス説明を三人称で書く。
- `## 特徴` — 箇条書きで 5 項目程度。数値・実装詳細を出さず本質を抽象的に書く。機能の羅列ではなく「何が嬉しいか」を読み手の言葉で書く。
- `## 画面イメージ` — 画像があれば載せる。テーブル 1 行 × N 列で並べ(`| 画面1 | 画面2 |` の下に `| ![](./docs/images/01-xxx.png) | ... |`)、枚数は 1 枚以上で可変とする。内容の薄い画面(設定画面等)は無理に入れず、画像は縦横比・サイズを揃える。
- `## 技術スタック` — 「レイヤー / 採用技術」の 2 列テーブルで書く(フレームワーク・UI・言語・DB・テスト等)。続けて `### 実装上の工夫` を箇条書きで 3〜5 項目書き、読み手が判断材料にできる粒度とする。内部実装名はファイルパス参照程度に控えめにする。
- `## ローカル起動方法` — `bash` コードブロックで「依存インストール → 環境変数(あれば `cp .env.example .env.local`)→ 開発サーバー起動 → `http://localhost:{port}`」を書く。直後にデフォルト動作の説明を 1〜2 行と、Runtime のバージョン要件を書く。必要なら `### 環境変数` を「変数 / 必須 / 例・既定 / 説明」のテーブルで書く。
- `## コマンド一覧` — `bash` コードブロックで主要コマンドを短いコメント付きで書く。
- `## ディレクトリ構成(抜粋)` — コードブロックに重要な階層だけを載せ、各行のコメントで中身を短く説明する。
- `## プライバシー / データ方針` — 個人情報を扱うサービスの場合に書く。何を保存し何を保存しないか、ログ方針、検索エンジンからの除外、同意・レート制限などを箇条書きで書く。

## 出力ルール

- 画像は `![](./docs/images/xxx.png)` の標準構文で書く。
- コードブロックの言語指定(` ```bash ` / ` ```ts ` 等)を正しく付ける。
- 冗長にせず、読み手が全体像を掴める分量にする。
- 文中に読点があれば文末に句点を付け、句点の有無や体言止めを一つの箇条書き・段落の中で混在させない。文法的に正しく、句読点の整った日本語で書く。

## 完成後の振る舞い

- README の全文をユーザーに提示し、「直したい箇所があれば指摘して」と一言添える。
- 指摘があれば修正して再提示する。
- ユーザーが「OK、README.md に反映して」等と承認したら、次を行う。
  1. `README.md` に反映する。
  2. `docs/readme` 等のブランチを切る。
  3. commit メッセージは `docs(readme): README を作成` の形式で書く。
  4. PR を作成し、URL を返す(タイトル・説明は日本語)。

## 秘書ちゃんモードとの連携

秘書ちゃんモード(`/company:secretary`)中に「README 作って」等と言われたら、このスキルのルールに沿って生成する。プロジェクトの `.company/state.md` に仕様・技術スタックが記録されていれば、それを優先的に材料として使う(聞き直しを減らせる)。
